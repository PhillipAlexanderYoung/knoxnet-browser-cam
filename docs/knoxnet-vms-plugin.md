# Knoxnet VMS Plugin Model

Keep `knoxnet-browser-cam` as a standalone open-source repo. Do not merge it
into `knoxnet-vms-beta` by default.

The recommended first integration is a sidecar service:

```text
Knoxnet VMS -> optional plugin/sidecar launcher -> knoxnet-browser-cam bridge
```

The bridge owns MediaMTX path allocation and RTSP URL generation. Knoxnet VMS
can treat the generated RTSP URLs like any other camera source.

## Recommended Path: Sidecar First

Run this repo's receiver and bridge independently, then add the displayed stable
RTSP URL to Knoxnet VMS:

```bash
cd /home/operator1/Documents/knoxnet-browser-cam
npm install
npm run dev:all
```

For production, run `receiver/dist/server.js` and `bridge/dist/server.js` under
systemd, PM2, Docker, or Knoxnet VMS's future plugin supervisor.

Benefits:

- The browser-camera project stays independently releasable.
- Knoxnet VMS does not need to vendor unstable frontend/receiver code.
- Users can upgrade, replace, or remove the sidecar without changing the VMS
  repository.
- The public phone app remains a static Cloudflare Pages site, while RTSP and
  WebRTC stay LAN-only.

## Later Integration Options

### Git Submodule

Use this if Knoxnet VMS needs source-level access while preserving separate
history:

```bash
git submodule add https://github.com/YOUR_GITHUB_USER_OR_ORG/knoxnet-browser-cam.git plugins/knoxnet-browser-cam
git submodule update --init --recursive
```

### GitHub Release Tarball

Use this for installer scripts or packaged Knoxnet VMS releases:

```bash
curl -L -o knoxnet-browser-cam.tar.gz https://github.com/YOUR_GITHUB_USER_OR_ORG/knoxnet-browser-cam/archive/refs/tags/v0.1.0.tar.gz
```

### npm Package Or Workspace Link

Use this later if the bridge exposes a stable library API. Today, the monorepo
is best consumed as a process/sidecar rather than as an npm dependency.

### Installer Script

Knoxnet VMS can later ship an installer command that clones or downloads this
repo, runs `npm ci`, builds it, and registers receiver/bridge services with the
local service manager.

## Contract For Knoxnet VMS

The stable contract should be operational rather than source-level:

- Phone app URL: `https://cam.knoxnetvms.com`.
- Local receiver signaling URL: `wss://<local-ip>:8787/ws`.
- Pairing URL shape:

```text
https://cam.knoxnetvms.com/?receiver=wss://<local-ip>:8787/ws&pair=<pair-code>&autostart=1
```

- Bridge API: local-only HTTP API on `http://localhost:8790`.
- VMS input: stable RTSP URLs generated by the bridge, such as
  `rtsp://<host>:8554/<camera-slug>`.

Keep that contract small. It lets Knoxnet VMS add browser cameras without
absorbing this repo's release cycle.
